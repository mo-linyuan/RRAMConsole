# RRAM芯片控制台

面向不同系列 RRAM 芯片的控制台。顶部选择芯片系列，目前仅接入 **I1003 系列**，现有报文、寄存器、配方和执行逻辑均属于 I1003，不适用于尚未接入的其他系列。

I1003 通过 UDP 控制板卡 FPGA，再由 FPGA 把 64 位 PKG 送进芯片的 NoC，用来完成 RRAM 写测试（配 reg[8]、批量写指令、停止、启动、查结束）。

## 芯片系列与扩展

板卡通信及首次上板排查见 [联调说明](docs/first_board_bringup.md)。本项目通过现有 FPGA 协议收发报文，不包含 FPGA 工程或固件扩展；软件发送完成不代表真实芯片已经测通。

`run.py` 使用公共入口 `rram_console.app`；`rram_console/chips/` 注册芯片系列并提供系列后端。现有 I1003 模块与导入路径继续保留，避免破坏旧脚本。

后端负责创建自己的通信链路、执行器、路由栏、器件配置、报文模板及序列面板，也负责收包解释和序列头信息处理。添加其他系列时，在独立模块中实现这些接口，再通过 `register_family(ChipFamily(...))` 注册；参考 `rram_console/chips/i1003.py`。只有实现并注册的系列才会出现在选择框中，不创建无法运行的占位型号。

不同系列可以使用完全不同的指令编码和执行流程；当前器件配置与模板仍是 I1003 专用界面。切换系列会加载对应后端、清空旧序列；连接或运行期间禁止切换。各系列设置分开保存，I1003 沿用原设置键名。

所有系列的 RRAM 阵列统一为 **128×128（16,384 个器件）**，规格集中定义在 `rram_console/hardware.py`；行、列编号均为 `0～127`。器件配置与 WRITEB 模板按此范围输入并校验，WRITEB 模板自动把行列转换成器件地址；旧模板中的 HEX 地址编辑时会兼容转换，保持原指令地址不变。

阵列尺寸与地址编码分别处理：I1003 的行列位域排列仍保留现有两种待确认编码，不能仅凭阵列尺寸确定。结构化序列导入与发送时拒绝无法映射到阵列的 WRITEB 地址。16,384 个器件不等于指令区容量，I1003 指令区仍为 8192 条，整阵列测试需要另行设计分批流程。

新导出的 JSON 序列头记录 `chip_family`，导入时校验与当前系列一致；旧文件未声明系列时按 I1003 处理。原始 HEX 不包含型号标识，不能自动推断其适用芯片。

## 运行

只用 Python 标准库，Python 3.8 以上即可。

```
python run.py                       # 启动调试台
python -m tools.fake_board          # 另开一个窗口：模拟板卡，离线调界面用
python -m unittest discover -s tests -t .   # 跑测试
```

连接真实板卡前关掉占用同一本地端口的网络调试助手。电脑有线网卡要设为 192.168.1.9，FPGA 的回包固定发往 192.168.1.9:8080。

旧命令行 `tools.fake_board` 仍可使用：调试台里把本机设成 `127.0.0.1:9081`，板卡设成 `127.0.0.1:9080`。它是理想化测试助手，会模拟执行结束；不代表芯片真实行为。日常离线调试推荐直接使用下方 GUI 模式。

界面设置自动保存在 `~/.i1003_console/settings.json`。

器件配置默认单个器件、重复1次。“操作范围”只区分单个器件、一整行、自定义范围；SET/RESET单独在“操作”选择，次数单独填写。切换范围不覆盖操作类型、脉宽或重复次数。首次升级会把旧默认4095次重置为1次，其他自定义次数保留；之后手动设置的4095次仍会保存。界面不展示个人来源或旧实验台名称。

单个器件只显示一个行号和一个列号，内部起止位置保持一致；整行只显示行号，列固定0～127；自定义范围才显示起止行列。单器件与整行模式生成报文时会按该模式规范化坐标，隐藏字段的历史值不参与扩大选区。所选范围模式随设置保存。

## 不连接板卡时调试

启动 GUI，在连接区把“连接模式”切换为“离线模拟”，选择场景，点击“启动模拟”。无需修改网卡 IP，无需另开服务；收发双方使用 `127.0.0.1` 的随机空闲端口，仍通过原有 UDP 收发、报文匹配和执行器处理。

| 场景 | 模拟行为 |
| --- | --- |
| 标准（无芯片回包） | Ready=1，FPGA地址1/2/3/4可读；芯片读请求不回复，适合默认写入流程和“板卡链路自检” |
| 寄存器读回（模拟） | 在标准场景上增加按目标核、RGN和存储区隔离的PKG写入/读回，用于核对寄存器、指令和路由 |
| Ready 保持 0 | Ready持续为0，检查执行器是否在写入前中止 |
| 全部回包超时 | 接收报文但不发送回复，检查超时、停止和断开连接 |
| 回包延迟（800 ms） | 延迟FPGA回复，检查超时及迟到回复；芯片仍不回复 |
| 间歇丢包（每 2 包） | 丢弃每第2个回复，检查Ready查询重试和读请求失败处理 |

建议先使用单器件操作一次、重复次数1。写入间隔默认0，不额外限速；控制间隔默认20ms，只用于独立控制报文，不再叠加到每条指令写入上。不再附加预计执行等待，4095次对应的26.523315秒仅作为名义脉冲累计换算显示。真实板卡操作前断开模拟，再选择“真实板卡”连接，原IP/端口设置保留；每次启动软件默认选择真实板卡，不自动恢复模拟连接。

标题栏、连接状态、收发日志和结果会明确注明“离线模拟”。结果中注明“不代表实物结果”。断开或关闭窗口会关闭模拟UDP服务，重新连接会清空模拟存储。

模拟器仅维护FPGA寄存器和PKG存储值，不执行WRITEB，不生成电流、导通结果或物理时序。即使选择寄存器读回场景，写启动值后也不会伪造reg[0]结束位；需要芯片结束回包的流程会按实际超时规则失败。实物选通和4200测量仍需上板验证。本模式不包含任何FPGA源码或固件修改。

## 笔记本显示与日志性能

初始窗口根据当前显示器的可用工作区设置大小，预留标题栏和任务栏空间，最小窗口不再按大屏尺寸强制撑大。顶部芯片选择和连接参数在宽度不足时分两行显示。主区左侧是器件配置/报文模板，右侧是发送序列，底部为通栏日志；窄屏也默认保留日志，顶部按钮可手动收起或展开。

布局采用紧凑间距，保留原字号：写入间隔在宽屏并入路由栏、窄屏换行；日志图例、跟随开关和工具按钮位于同一标题栏。参数区默认只显示两行时间摘要与简短报文预览，完整说明通过“详细参数”展开。“生成序列”与页签同排，不单独占行。

左右区域、底部日志及模板导航全部使用Tk原生PanedWindow分隔条，由Tk管理鼠标跟踪、预览与释放，没有Python鼠标抓取或覆盖鼠标的自绘层。分隔条宽8像素，拖动时显示位置预览，松开后一次应用尺寸；拖动过程不持续重排整块表单、树表和文本。表单滚动条固定占位，避免因反复显隐导致换行、宽高和滚动区域循环变化。窗口缩放交给原生布局管理器，不再用定时器强制纠正分隔位置。面板使用普通Frame容器，按钮和标签页使用原生边框绘制，避免大面积Canvas与拉伸透明图片的重复绘制；文字换行更新在16ms窗口内合并，并忽略只有高度变化的尺寸事件。

较窄表单提供水平滚动，“生成序列”固定在页签行右侧；字体仍沿用系统 DPI 缩放，不通过缩小字体强行塞入小屏。已有 Windows DPI 感知在程序启动时设置；在不同缩放的显示器之间移动后若出现模糊，可在目标屏幕重启程序，当前尚未实现完整的运行时跨屏 DPI 重建。

整个窗口使用固定尺寸的内容容器隔离连续缩放事件。拖动窗口边框时外窗正常改变大小，内容暂时保留原布局（缩小时裁切、放大时出现背景空白）；停止变化90ms后按最终尺寸统一重排。最大化与恢复也走同一路径，最终重排仍有一次绘制开销，不声称每帧实时重排。未使用系统钩子或修改Windows全局设置，通信线程不受此机制暂停。

日志由主线程分批插入，每批最多处理200个队列事件，批次之间让出事件循环；每批只滚动一次。向上查看历史日志或取消“跟随最新”时不强制跳回底部。可见日志保留数量仍有限制，日志只保留在内存中，点击“保存”才导出当前可见文本。

超过1500行的序列表分批绘制，每批最多200行，格式化预算4ms，批次间隔16ms。显示期间可滚动或清空，编辑与运行在显示完成后恢复；替换、清空或关闭窗口会取消旧绘制任务。日志同时限制单批预览字符数，超长行与大接收报文只展示摘要，不自动创建运行记录。图标的抗锯齿形状缓存复用，减少启动时重复计算。

可使用 `python -m tools.profile_ui_stress --output artifacts/ui-stress.json` 离线测量大列表、持续日志和滚动响应，增加 `--sync-render` 可比较同步绘制。当前本机5000行测试中，分批显示将载入请求返回时间从75.3ms降至4.5ms，测试心跳的最大间隔从75.6ms降至24.5ms；完整显示耗时从94ms增至552ms，以分散绘制换取交互响应。这些是本机离线测量，不代表笔记本实测帧率。

修改发送/写入间隔仅更新相关参数摘要，不刷新报文或重建序列表；替换、插入和移动条目只更新受影响行。需要完整刷新时批量更新且跳过未变化行，保留当前选择与滚动位置。进度消息在每批中合并显示，并在最终结果前刷新，避免进度覆盖完成状态；预览和执行预检只展开所需首帧，但仍验证所有指令段。

可使用 `python -m tools.profile_ui_actions --output artifacts/ui-actions.json` 离线测量1000行序列的编辑开销，命令不会连接板卡。本次本机对比中，间隔编辑中位数约50.6→2.3ms，单行替换44.9→19.8ms，未变化列表刷新73.3→10.4ms；这些是该离线测试的Tk事件处理耗时，不是所有设备的屏幕帧率保证。

## 执行结果与实验记录

器件配置通过“生成序列”加入右侧，再用“运行选中/运行全部”执行。报文模板提供“直接发送”“加入序列”和“替换选中”：直接发送执行当前模板，不加入或修改序列，复用公共参数校验、读回等待与停止任务逻辑；另外两项仅编辑序列，不发送报文。常规操作不再弹二次确认。导入菜单直接选择替换或追加，选完文件即载入。未连接、忙碌或未选择条目等提示写入日志；参数错误、文件读写或连接失败仍显示错误信息。运行期间的编辑锁与发送前参数校验继续生效。

默认生成且仅生成**写reg[8] → 写入指令（含STOP） → 发送启动报文**，发送后立即报告“报文已发送”。主面板不再包含启动后等待、4200提醒、芯片回包核对开关，也不自动添加等待或结束轮询。Forming与RESET的控制指令相同，界面仅保留SET/RESET。Ready查询、FPGA读写、NoC报文和发送间隔保留。名义选通累计仅为参数换算，不用于延迟任务或判定芯片完成。

首次升级会自动关闭旧设置中默认开启的上述三项读回选项，保留器件、脉冲和重复次数参数。之后用户手动开启的读回选项正常保存。已导入或已经生成的序列不自动改写；需要使用新默认流程时请重新生成序列。

右侧“诊断步骤→板卡链路自检”读取FPGA Ready、接收使能和boot_mode，再发送只读reg[8]的PKG，从FPGA地址0003回读暂存核对；载入后点击运行全部。不会写RRAM、配置芯片寄存器或启动核，也不等待芯片回包。通过只证明FPGA保存了PKG，不证明芯片接受、执行或导通。需要读回时可载入“可选读回核对”，或从寄存器/指令读模板加入对应报文；超时或不一致仍判为失败。

配置与流程集中在左侧，右侧诊断菜单不再重复单器件、整行或Forming配置。报文模板中的单条和批量WRITEB合并为“写入WRITEB指令”，条数默认1，可选择是否追加STOP；只写入、不自动启动。推断NI使能与组合自检不再作为普通报文模板。读取/写入指令的地址都校验0～8191，模板选项与数值范围在构造时报错。旧模板名称仍兼容读取，但不显示重复树项；未知组合条目仅提供只读预览，避免编辑时被截断成首条报文。普通模板的字段编码经过离线核对；行列编码、路由与电气选通仍需实物验证。

- **先检查再发送**：启动前检查整个任务，拒绝越界地址、溢出数据、负数或无效等待时间，避免发到一半才发现后续参数有误。
- **核对失败就停止**：勾选的 reg[8]、首条指令核对，遇到超时或数据不一致立即中止后续步骤。未收到结束回包也判为失败。纯发送成功只显示“已发送”，不代表芯片执行成功。
- **统一读操作**：原始 HEX 的单帧读请求、FPGA 模板读请求和芯片读请求都会等待匹配回包；写操作不会自动重发。
- **过滤无关回包**：仅目标板卡 IP/端口的报文可以用于应答；芯片回包按 send-out 类型、地址和反向源/目标坐标匹配。未匹配或其他来源的包仍显示并记录，但不用于核对。回包格式与真实芯片的兼容性仍须实测；协议没有事务编号，同一请求的迟到回包无法完全消歧。
- **明确任务状态**：右侧序列显示运行进度、核对结果、失败与停止状态；运行期间禁止增删、移动、替换或导入序列。任务使用启动时的参数快照。“控制间隔”用于单独控制报文，“写入间隔”单独限速指令写入，默认0。Ready检查仍按用户设置逐条执行，写入仍是现有协议的一帧一UDP包，未增加FPGA扩展。
- **停止任务**：按钮始终可点击；运行中取消后续发送、Ready/读回等待和预计执行等待。停止、结果和进度使用独立控制队列，不排在大量文本日志后面。空闲时显示当前没有发送/等待任务。已经启动的芯片操作不会自动终止，当前未实现芯片级紧急停止指令。“UDP 已打开”仅表示本地通信链路已打开，芯片状态需查询确认。

写入只在界面显示首末报文与计数，不自动保存逐帧TX。为避免Windows的粗粒度Event.wait把20ms放大为约31ms，短发送间隔改用分段sleep与停止标志，取消检查间隔不超过10ms；不修改全局计时器，不忙等。写入间隔0不会省略Ready检查，也不代表板卡已经接收所有UDP包或RRAM已经执行。

日志不自动写入文件，也不自动创建运行记录目录；点击日志标题栏的“保存”，选择路径后才导出当前可见文本。取消保存不会生成文件。“清空”只清除界面日志，关闭窗口会丢弃未保存日志；已有的历史记录文件不会删除。超长报文仅显示摘要，批量指令仅显示首末报文，手动保存的内容与当前界面一致。

新增系列后端可实现 `run_metadata(items, options)` 提供自己的序列及参数序列化；各系列负责自身命令和读回规则；GUI不自动将这些元数据写入文件。离线模拟测试只证明软件逻辑，不等于真实芯片验证。

## 目录结构

```
i1003/
  protocol/       协议层：纯函数，不依赖任何其他模块
    fpga.py         FPGA 帧格式和地址定义（依据 common_reg.sv、decode.v）
    pkg.py          NoC 64 位 PKG 编解码、路由 Route
    isa.py          指令编码（WRITEB、停止指令）、reg[8] 写验证配置、10 MHz 时序换算
  transport/
    udp_link.py     UDP 收发、请求与回包配对、查芯片 Ready
  model/
    items.py        序列条目：每种条目知道怎么展开成帧、怎么序列化
    sequence_io.py  导入导出：本项目 .json、网络调试助手 .ini、纯文本
  engine/
    runner.py       按序列执行，事件通过 RunEvents 回调报告，不碰界面
  recipes/
    write_test.py   RRAM 写测试配方：WriteTestSpec → 序列条目 + 摘要
  ui/             界面层
    theme.py        颜色、字体、样式
    context.py      面板之间的接口（AppContext）
    templates.py    报文模板的数据定义
    settings.py     设置保存
    app.py          主窗口：组装各部分，实现 AppContext
    panels/         各面板，只依赖 AppContext，互不引用
tests/            单元测试 + 界面冒烟测试
tools/fake_board.py   模拟板卡
run.py
```

依赖方向是单向的：`protocol ← transport ← engine`，`protocol ← model ← recipes`，`ui` 在最上层。除 `ui` 外都不 import tkinter，所以协议、配方、执行器都能脱离界面单独测试和复用，比如以后写批量测试脚本时直接用 `recipes` + `engine`。

### 常见改动应该改哪里

| 想做的事 | 改哪里 |
|---|---|
| FPGA 加了新地址（比如复位寄存器） | `protocol/fpga.py` 的 `Addr`，再在 `ui/templates.py` 加一个模板 |
| 确认了行列在器件地址里的排法 | `protocol/isa.py` 的 `CellEncoding` |
| 确认了源节点坐标或 RGN | `ui/panels/toolbar.py` 里 `RouteBar` 的默认值，或 `protocol/pkg.py` 的 `Route` |
| 芯片时钟不是 10 MHz | `protocol/isa.py` 的 `CHIP_CLK_HZ` |
| 新增一种测试流程 | 在 `recipes/` 下新建配方，返回 `List[Item]`，界面只需加按钮调用 |
| 新增一种条目（比如等外部触发） | `model/items.py` 加类，`engine/runner.py` 加执行分支 |

## 选通参数

默认参数为基时间254、时间倍数255、验证次数0、重复1次，生成 `reg[8] = 00FF_00FE`、1条WRITEB和1条停止指令。重复次数可手动设置，不由阵列尺寸或通信协议规定。界面不按选通秒数反推次数。

当前 FPGA 的芯片时钟固定为 10 MHz；软件显示该频率，并在详细参数中换算脉宽和名义累计时间，界面不能调整实际硬件时钟。重复 WRITEB 是否在指令边界存在关断间隙，需要实测。指令区共 8192 条，预留一条停止指令后最多写 8191 条 WRITEB。

“重复次数”右侧实时显示总选通时间（名义）：`基时间 × 时间倍数 ÷ 10 MHz × 每器件重复次数 × 器件数`，并分别显示单次脉宽和每器件累计时间。该值只累计配置脉宽，不计验证重试、指令间隙、通信及软件等待，不代表实测的连续选通时间。参数无效时显示 `—`。

界面同时显示**写入等待预算**：`（WRITEB 条数 + 1 条停止）× 写入间隔`，默认写入间隔0，对应额外等待预算0。若主动把写入间隔设置为20ms，4095次仍会产生 `4096 × 20 ms = 81.920 s` 的人为等待；控制间隔20ms不会再被叠加到写入循环。对应名义脉冲累计仍为 `26.523315 s`。写入阶段还包含Ready查询、UDP、记录写入和调度开销，实际耗时见日志；预算不是整个任务的精确预估。

写入在发送启动命令之前完成；芯片收到启动命令后才执行已写入的WRITEB。日志单独记录写入开始、完成或中断、实测指令写入耗时及软件任务总耗时。内部结果的 `download_s` 是所有指令写入步骤的实测软件耗时之和，`elapsed_s` 是软件任务耗时；二者均不代表器件实际导通时间。不再追加启动后的软件等待，也不按名义脉冲时间延长任务。

## 从 FPGA 工程确认的事实（I1003_NOC_1012）

| 报文 | 作用 |
|---|---|
| `00 01` / `80 01` | 读 / 写 `noc_in_ready`（FPGA 是否接收芯片输出），复位为 1。同事给的"初始使能"其实是读 |
| `00 02` | 读芯片 `pad_Noc_i_3_Ready` |
| `80 03` / `00 03` | 发 PKG 给芯片 / 读回 FPGA 最后发出的 PKG |
| `00 04` / `80 04` | 读 / 写芯片 `boot_mode` 引脚，复位为 1 |
| `80 00` | **禁止**：bit63 会打开以太网测速模式 |

- 给芯片的时钟都是 10 MHz（RTC 为 6.52 MHz）。
- 芯片输出：FPGA 检测 `noc_in_valid` 上升沿，把 64 位包以 8 字节 UDP 包发给电脑。
- 一个 UDP 包里可以有多帧，decode 逐帧处理（"批量快速发送"依赖这一点）。

## 待确认 / 待修改

- `por_rst_n`、`sys_rst_n` 在 FPGA 里接成常数 1，芯片从未被复位。这是芯片不回包的头号嫌疑，建议 PLL 锁定后再释放，并加一个可由电脑触发的复位地址。
- `noc_out_valid` 固定拉高 10 个周期、不等握手，同一个包可能被芯片接收多次。
- 源节点 30、RGN=0 是推断；回包要回到片外口，需要哪种 RGN/HEADER 手册没写。
- 器件地址里行、列的排法未确认（界面里两种都可选，只测第 0 行时没有区别）。
- 写验证"验证次数"大于 0 时芯片的实际行为未确认，I1000 实验台用的是 0。

软件等待和轮询等待已从报文模板移除；旧配置中的相关开关不再读取。导入旧序列时跳过标记为estimated_execution的自动预计等待步骤，并在导入日志说明；不会修改原文件。底层保留旧条目解析，手动编写的通信间隔兼容读取。
