# I1003 器件选通链路核对

核对日期：2026-10-23。

后续软件更新：一键测试已改为直接填写基时间、时间倍数、验证次数及重复次数，默认使用师姐的 `00FF_00FE` 和 4095 次。下文对 1 ms 默认值、8 s 场景的描述是本次核对时的旧软件状态；FPGA 与芯片初始化部分的待确认事项仍保留。

目标：沿用师姐的 RRAM 核心测试流程，用当前 PC→UDP→FPGA→I1003 NoC 通路选通指定器件，配合 4200 施压与测量。

本次是文档、RTL 与上位机源码核对，没有连接板卡、下载 bitstream、发送实验命令或测量器件。下列 RTL 结论描述给定工程的源码，不能确认板上当前下载的版本。

## 1. 核心流程对照

| 步骤 | 师姐的 I1000 平台 | 当前 I1003 软件 | 核对结果 |
| --- | --- | --- | --- |
| 配写脉宽 | reg[8]，实操记录要求 Timeout Times=0，示例 00FF_00FE | 写 reg[8]，默认验证次数 0，但默认脉宽 1 ms | 步骤一致，默认参数不完全一致 |
| 下载单器件指令 | long_tx 重复 WRITEB，例如 4010_0002，共 0FFF 条 | 从地址 0 逐条写 WRITEB，支持重复 4095 次 | 核心意图一致 |
| 追加停止 | 地址 0FFF 写 70F0_0000 | 在最后一条 WRITEB 后追加 70F0_0000 | 与师姐流程一致；I1003 部分手册正文未单独解释 CTRL 类型 15 |
| 启动 | reg[0]=1，然后触发旧 FPGA 的 tx_cfg | 通过 NoC 写 reg[0]=1 | 业务动作一致，底层发送机制不同 |
| 外部测量 | 启动后在 4200 点 run | 启动后弹窗提醒操作 4200 | 步骤一致，需要匹配实际测量窗口 |
| 结束检查 | 读 reg[0]，记录 0x80 | 轮询结束位 0x80 | 与 I1000 流程一致；I1003 文档的结束状态文字有位数笔误，需保留实测原值 |

师姐平台的 tx_cfg、long_tx_cfg 是旧 FPGA 的发送触发接口，不是要再发给 I1003 的芯片指令。当前工程由 decode.v 产生 write_en/read_en，再由 common_reg.sv 写地址 3 触发 NoC 输出。

I1000 的 OP 与 I1003 的 PKG TYPE 编号不能直接照搬：

| 动作 | I1000 OP | I1003 PKG TYPE |
| --- | --- | --- |
| 写核寄存器 | 0 | 4 |
| 读核寄存器 | 1 | 0 |
| 写指令区 | 2 | 5 |
| 读指令区 | 3 | 1 |

这些编号描述不同层次的接口；当前软件按 I1003 的 TYPE 包装，没有直接照搬 I1000 的 OP。

## 2. FPGA 中已经确认的实现

源码根目录：`D:/DataCenter/FPGA/I1003_NOC_1012/I1003_NOC_1012.srcs/sources_1/`。

### PC 与 FPGA 寄存器

依据 `common_reg/common_reg.sv`：

- 地址 1：读写 FPGA 输出的 noc_in_ready，即 FPGA 是否准备接收芯片输出；复位值 1。
- 地址 2：只读 noc_out_ready，即芯片是否准备接收 FPGA 发来的 PKG。
- 地址 3：写入 noc_out 并触发 noc_out_valid；读出 FPGA 的 noc_out 保存值。
- 地址 4：读写 boot_mode，FPGA 寄存器复位值 1；部分芯片手册没有给出 boot_mode 的完整启动要求。
- 地址 0：含以太网测速开关，不作为芯片选通命令使用。

因此 `00 02` 返回 `00 00 00 00 00 00 00 01` 的具体含义已经能由源码确定：芯片 Ready 引脚采样值为 1。它不是寄存器写入、指令执行或器件导通的确认。

`00 03` 读回一致只能确认 FPGA 保存了该 PKG；不构成芯片已经接收或执行的证明。通信指令文档第 4 步的“证明 FPGA 已把该 64bit 发给芯片”应按此边界理解。

### 芯片复位

`top/sys_top.sv:71-72`：

```verilog
assign sys_rst_n = 1'b1;
assign por_rst_n = 1'b1;
```

结论：当前 RTL 不会主动给芯片这两个引脚产生低有效复位脉冲。PLL locked 接到 FPGA 内部 rst_n，并没有接到上述芯片复位输出。

这是一项需要优先处理的初始化缺口，但不能据此直接断言芯片没有任何内部上电复位，或认定所有不回包现象都由它引起。复位次序、保持时长、boot_mode 采样要求需要芯片完整上电规范。

### FPGA→芯片握手

`common_reg/common_reg.sv:41-79` 使用十级移位寄存器展宽 Valid，输出逻辑没有使用 noc_out_ready 来结束一次传输。

PLL 配置和生成代码显示：控制逻辑 sys_clk 为 10 MHz，芯片 clk_sys_rram 也为 10 MHz。孤立的一次写入会产生约 10 个控制时钟周期、约 1 μs 的 Valid。若芯片按每周期 Valid && Ready 接收，存在同一 PKG 被接收多次的风险；实际是否重复必须看波形或芯片接口实现。

PC 在发送前查询 Ready，不能代替 FPGA 在实际传输时完成握手。应以芯片侧时钟和接口时序要求实现：保持数据与 Valid，确认接受后撤销，避免一次 PC 请求触发多次接受。

### 芯片→FPGA 回传

`ethernet/ethernet_app.sv` 通过同步后的 noc_in_valid 上升沿产生一次收包事件，再锁存 noc_in。它不是按每周期 Valid && Ready 接收的完整队列。

若芯片连续多个周期输出不同 PKG、Valid 不拉低，则当前逻辑可能只接收第一个事件；若 FPGA 读寄存器回复和芯片回包事件同周期出现，read_valid 优先，源码没有对应的回包缓存仲裁。两项均为源码可见的丢包风险，尚无本次实测。

## 3. I1003 初始化需要补查的地方

依据 `I1003芯片手册（部分）.md:655-681`：

- reg[7][7:0] 是 Pelement clk Enable，复位值为 0。
- reg[9-10] 是各 PE 内的 RRAM 计算核心使能，复位值为 0。

当前 `i1003/recipes/write_test.py` 的自动序列从配置 reg[8] 开始，没有配置 reg[7]、reg[9]、reg[10]。

“使能字段存在且默认 0”已有文档依据；“WRITEB 一定依赖这些字段且是当前不选通的唯一原因”还没有芯片 RTL 或实测依据。

若芯片设计确认这些字段需要由上位机配置，优先按目标 PE/阵列配置相应位，并保留其他模式位；不要把全开所有 PE、所有阵列当成既定前置流程。手册对 reg[9-10] 的说明偏向计算路径，需确认其是否也门控 WRITEB。

源坐标 (3,0) 有手册中 NOC_offchip3_BASE 的映射作为线索，不是毫无依据；但该 MMIO 映射不能单独证明片外注入包的全部回程规则。正文明确 RGN=0 为 NoC 加速核目标区；NI 配置中的 HEADER=offchip 是另一个上下文，不能直接把外部请求的 RGN 改为 2。

手册还列出 NI reg[0][31:24] 节点使能。其是否门控外部配置请求、返回包，或只用于特定发包路径，需要进一步确认；不能仅凭复位值为 0 判断所有访问均被关闭。

## 4. 时间与“持续选通”的边界

按本工程芯片时钟 10 MHz、Timeout Times=0 计算：

- 师姐实操值 `00FF_00FE`：254 × 255 × 100 ns = 6.477 ms。
- 重复 4095 次，对应名义脉冲累计时间约 26.523 s。
- 当前软件默认 1 ms、4095 次，对应名义累计时间约 4.095 s。
- 当前“持续选通 8 s”场景按 1 ms 生成 8000 条 WRITEB，再加一条停止指令。

这些是根据字段和时钟算出的名义时间，不是本次测得的选通波形。重复 WRITEB 是否在指令边界短暂关断，需要测量；不能把累计脉冲时间直接当成无间隙的直流选通。

当前“一行遍历 128 个器件”场景给每个器件写一条 WRITEB，不等同于每个器件都维持数秒。师姐 traversal 的内部行为不能仅凭参数名称确定，需要旧 FPGA 的 traversal 实现或实操波形。

## 5. 下一步的最小验证顺序

1. 记录实际下载的 bitstream 和接线，确认芯片供电、时钟、boot_mode 与复位要求。
2. 用 ILA 检查一个 PKG 在芯片接口上只完成一次接受；现有 XDC 已配置 NoC 数据及 Ready/Valid 调试探针，实际使用需匹配 bitstream 与 ltx。
3. 先读核寄存器/指令区，确认回程；写 reg[8] 后读回相同值。若读不到，结论是该次访问未验证，不能直接断言器件绝不可能选通。
4. 确认目标 PE/阵列的初始化使能条件后，固定一个核、一个 PE、一个阵列、第 0 行的单个器件，下载重复 WRITEB、停止指令并启动。
5. 用已确认的 4200 电压、栅压及限流条件，比较未启动、选中目标、改选其他器件时的响应，并记录测量时间与选通窗口。

第 0 行可暂时避开软件中两种行列编码的分歧，但不能由第 0 行测试确认非零行的编码正确。不要仅因没有测到电流就盲目把所有 NoC 地址乘 4。
